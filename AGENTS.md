# Project guidance

- Full recomputation after a disruption is the bounded strategy run afresh on the same existing cohort and fixed prefixes, not an optimum certificate. Preserve can rescue a known valid plan when the new search truncates; compare coverage before cost, flag different served IDs, and report fee/time/hop allowances explicitly. `benchmarks/disruption-results.csv` and `docs/disruption-report.md` contain reproducible paired measurements and exact small-cohort checks.
- Dynamic simulation changes are surprise events applied before each tick's execution. `scenario()` is the restart input; `effective_scenario()` is the current rail/service view. Controls merge per rail/field for the next tick and commit atomically with RNG, reservations and events. See `docs/disruptions.md` for the explicit preservation/recompute/adaptive contract and churn denominator.
- A disrupted payment can retain only its executed/in-flight prefix while awaiting a suffix. `has_complete_plan()` distinguishes this from a usable route; `next_hop == route.hops.len()` can be a valid intermediate queue. Never index that queue's next hop without checking. In-flight arrivals and sunk fees are immutable; replacement suffixes exclude all previously visited prefix institutions.

- The reproducible benchmark suite lives in `benchmarks/`, with `scripts/benchmark.py` supervising fresh workers. Preserve censored/error observations and distinguish solver time from whole-worker CPU/RSS. The 512 MiB RSS guard is sampled and can overshoot; `ps`/CPU metadata need host access on macOS. Never call a timeout infeasible. Window projections exclude carry-in/background demand; their independently audited one-rail certificates prove feasibility/minimum fee only, not the full elapsed/lexical optimum.
- Measured search sensitivity includes equal-fee assignments, late incumbent discovery from participant ordering, reversed deadline-to-ID ordering, and candidate resource-vector storage. Simulation queue samples occur after ticks and can be zero during in-flight SLA failures. See `docs/benchmark-report.md`; thresholds are specific to the recorded machine/limits, not general capacity promises.
- Benchmark instrumentation is opt-in with `search-stats`; ordinary builds compile out every counter expression. Use separate release builds for timings and counters and compare deterministic results. Counters are calling-thread aggregates, reset explicitly, and never affect pruning or termination. See `docs/benchmark-method.md`.
- A benchmark worker can exit between a `wait4(WNOHANG)` poll and a watchdog kill. Tolerate `ProcessLookupError` on that kill, still reap once with `wait4` for exit/resource accounting, and preserve the observed censoring reason. Do not convert unrelated supervisor errors into successful benchmark records.

- Keep `src/network.rs` and `src/demo.rs` independent of Ratatui and Crossterm. The library owns data, validation and aggregate calculations; the binary owns interaction and rendering.
- This foundation is synthetic and USD-only. Amounts are integer cents (`u64`); aggregate sums use `u128`. Opening balances are input data, never reduced by loading or viewing payments.
- Rails describe shared services and explicit membership, not directed graph edges. Payments are unassigned instructions; validation does not promise a feasible route or sufficient liquidity.
- `demo_network()` must remain deterministic, including collection ordering. The fixture has 6 institutions, 4 rails, 12 payments, USD 1,000,000.00 opening liquidity and USD 225,001.50 payment volume.
- Rail IDs/display names are `RTP`/RTP, `FEDNOW`/FedNow, `ACH`/ACH and `FEDWIRE`/Fedwire, in that order. These names are recognizable U.S. vocabulary; membership/topology, fees and timing remain synthetic. The demo has all rails available, no transaction ceilings and no delivery deadlines. The demo leaves batch capacity unlimited; availability schedules and actual network rules are not modeled. FedNow deliberately reuses RTP's synthetic inputs; this does not claim real-world equivalence. Keep the Rails ID column wide enough for the seven-character `FEDWIRE` at 80 × 18.
- Detect dependency versions from `Cargo.toml` and `Cargo.lock`, then query Context7 before changing library API usage. Ratatui is pinned to 0.30.0; use its Crossterm re-export to avoid conflicting event types ([Crossterm Version and Re-export](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-crossterm/README.md)). With default features disabled, retain `layout-cache` ([Breaking changes](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/BREAKING-CHANGES.md)).
- Run relevant tests between changes, make atomic checkpoint commits, and create a PR only when directed. Single-payment static routing belongs in the terminal-independent library; no settlement engine or external solver is used.
- `cargo run --locked -- --demo` is the supported launch. Keep help and argument validation before terminal initialization. The UI needs 80 x 18; TestBackend checks minimum-size rendering and selection-driven scrolling. Actual PTY checks must also verify exit status and terminal modes after q, Esc and Ctrl-C when lifecycle code changes.
- `try_init` installs a panic hook but can return after partial setup. Always attempt restoration after initialization or event-loop errors ([Terminal initialization and restoration](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/src/init.rs)). The console blocks on input while paused and uses bounded host pacing while running; no wall clock enters the simulation.
- `route_payment` validates the network and the supplied instruction, including external instructions absent from `network.payments`. Rails connect every pair of members bidirectionally. Every hop carries the same USD principal and incurs the rail's fixed fee and latency; opening balances remain descriptive, not spendable or reserved routing capacity.
- Routing minimizes total fee, then latency, hop count, and the lexical sequence of `(rail_id, sender, receiver)`. Exact simple-path search is sufficient because fees and latency are nonnegative. Do not prune equal-cost paths or keep only the cheapest prefix at an institution when a delivery deadline can matter. Worst-case search is exponential; this is a small-network reference.
- The single-payment constraint fields are `Rail.available`, `Rail.max_amount_cents` and `Payment.max_delivery_minutes`. A ceiling is positive and inclusive, applies to principal excluding fees on every hop, and is not aggregate throughput. A deadline is inclusive and sums all hop latencies; zero allows only zero-latency routes. `None` means unconstrained. All inputs remain USD; no FX or additional currency model is implied.
- Keep the bounded-walk dynamic-programming oracle in `tests/routing_oracle.rs` independent of production search helpers. It checks fee/latency/hop optima and route witnesses across small exhaustive networks; focused tests cover lexical ties and wide totals. Run `cargo run --locked --example route_one` for asserted, hand-calculated constraint counterexamples without terminal initialization.
- `Rail.batch_capacity_cents` is a separate synthetic principal budget for one optimization batch: every hop consumes its full payment amount from the same rail budget across all members and both directions, excluding fees. `None` is unlimited; `Some(0)` is valid and permits no batch use. Capacity never replenishes or nets within a batch. Institution opening balances stay descriptive. Single-payment routing deliberately ignores this batch-only field. Demo rails default to unlimited; simulation uses separate recurring service capacities.
- `batch::optimize_batch` routes exactly the supplied batch, validates the entire network and all supplied instructions, and rejects duplicate batch payment IDs. It returns a full plan or infeasibility, never a partial allocation. Assignments are ordered by payment ID and usage by rail ID; ties minimize total fee, summed latency, total hops, then route-hop sequences in that payment order. Returned usage and totals use `u128`; no inputs or budgets are mutated.
- Batch search retains all feasible simple paths, then backtracks over joint assignments. Do not reduce candidates to each payment's cheapest route or cheapest prefix: the six-assignment oracle counterexample has greedy cost 11 cents versus optimum 4, and independent minima overuse capacity. The sum of cheapest remaining route fees is only an optimistic pruning bound; prune strictly greater fees to preserve ties. This bound made the unchanged 12-payment demo practical after prefix-only pruning exceeded a minute. Keep the test oracle independent: it materializes bounded walks and the Cartesian product, checking capacity on complete assignments rather than sharing production pruning.
- Run `cargo run --locked --example route_batch` for the asserted six-assignment and multihop greedy counterexamples. `tests/batch_oracle.rs` makes 6,342 deterministic full-rank comparisons against the independent bounded-walk/product oracle; the oracle intentionally includes cyclic witnesses, so its raw walk count can exceed the number of simple routes.
- Scheduled execution uses a separate terminal-independent `scheduling` module. See `docs/time-model.md`: integer `u64` minutes, finite explicit rail departures, unlisted minutes closed, free waiting, departure-sampled fee/latency, shared per-departure principal budgets plus unchanged static batch budgets. `TimedPayment` adds release and absolute deadline; its underlying delivery budget includes waiting from release. Do not infer calendar rules, replenishing batch budgets or in-flight occupancy. Static APIs and demo data keep their existing meanings.
- `scheduling::optimize_schedule` retains all feasible simple paths and departure choices, then jointly allocates both rail and slot budgets. Free waiting lets cycle removal preserve downstream departures; this is why simple paths remain sufficient despite time-dependent latency. Never keep only a cheapest or earliest prefix: later departures may arrive earlier, and a more expensive prefix may free a contested future slot. The sum of unconstrained lexicographic `(fee, elapsed, hops)` minima is only an optimistic bound; prune strictly greater scores to preserve lexical ties.
- Scheduled verification uses an independent bounded-walk/full-product oracle, with deadlines on completed walks and capacity checks on complete batches. The 3,940 generated comparisons include overlapping services, cycles, zero latency, releases, deadlines, fee/latency overrides and both budgets. Focused counterexamples establish greedy 11 versus optimum 2 or 4, missed connections from waiting, and a necessary expensive prefix. The unchanged 12-payment demo has a separate explicit minute-zero timetable fixture costing 60 cents, proven by a 5-cent per-payment lower bound; do not claim this covers arbitrary timetables.
- Run `cargo run --locked --example schedule_batch` for independently enumerated timed assignments and printed execution witnesses. Timestamps are sparse, so a `u64::MAX` departure does not expand intermediate ticks. Arrival overflow is malformed input even for unused/closed slots. All schedule validation must finish before empty-batch or infeasibility returns.
- Continuous simulation has a separate contract in `docs/simulation.md`: recurring per-minute service budgets are distinct from finite batch/timetable budgets. Keep controls and execution independent of terminal and wall-clock code. Prioritize conservation failures and nondeterministic replay over routing quality; never retain an unbounded payment history or silently drop overload/expired work.
- `simulation::Simulator` uses fixed SplitMix64 draws, integer-minute transactional ticks and checked `u128` totals/time. Tick order is rail reset, due settlements, arrivals, FIFO routing/departures (including immediate zero-latency chains), then inclusive deadline expiry. Opening balances remain descriptive. Only actual departures consume principal capacity and incur fees; settlement does not replenish capacity.
- The initial `CheapestStatic` policy calls `route_payment` against current open/usable rails and remaining SLA, then pins the path. It does not reserve future capacity or predict service windows. After an SLA miss, drain an outstanding hop: final arrivals complete late; intermediate arrivals expire. Never dispatch another hop or count a second SLA failure. Overload rejection counts as an immediate SLA failure and stays separate from deadline expiry.
- `step` ignores the run flag; `tick` respects start/pause; `restart(seed)` restores a fresh paused state. Driver pacing must never change RNG consumption. Generate all attempt samples before admission decisions. Bound active work and retained history explicitly; completed/expired/rejected records are not retained. Numeric/invariant errors must roll back the entire tick, including RNG and event sequence.
- `tests/simulation_replay.rs` checks 128 scenarios across 10,240 event batches using an independent event accountant plus exact replay/grouped restart. Two 100,000-tick stress cases peak at 9 and 8 active payments and retain 17 events each; disconnected overload records 299,992 rejections. Run `cargo run --locked --example simulate -- 10000 42` for a headless replay demonstration with explicitly accelerated synthetic timings. The existing router is still exponential; do not claim arbitrary-topology throughput or global optimization quality.

- `scalable::plan_schedule` and `RoutingStrategy::Reserved { limits }` use an independent bounded label search. Exact `routing`, `batch` and `scheduling` searches remain unchanged oracles. A missing heuristic plan means unresolved, never infeasible. Full plans enforce both static batch and departure budgets; simulation rejects static batch budgets and reserves recurring departure capacity, including earlier commitments, before route acceptance. Fees accrue only on actual departure.
- Reserved execution stores departure timestamps aligned with simple route hops. Before each transactional tick commits, reconstruct all future reservations from active witnesses plus current departures and compare against the sparse ledger. Never consume another hop after the deadline, drop reserved work, or let ordinary admission release prior-tick commitments; the explicit disruption transaction may replace future suffixes. Same-minute zero-latency multihop usage is additive; prune past reservation entries and keep storage bounded by active path lengths.
- The bounded policy tries FIFO, deadline/amount, amount/deadline and reverse orders, then at most `max_repairs` pair trials for heterogeneous groups of at most 16. Safe label dominance includes visited-node and constrained-resource subsets. Per-node, total-label, expansion and candidate limits may lose optimal or feasible paths; retain truncation diagnostics. A recurring fee lower bound is valid only for positive constant latencies and remaining SLA <=64; it relaxes competition/windows and must not be applied to finite fee/latency overrides.
- `docs/scalable-routing-report.md` and `docs/scalable-routing.md` distinguish each measured experiment, unserved/censored cases and every certified fee gap. Keep raw runs and exact or independently certified optima; report zero-optimum and unresolved gaps explicitly. Do not call fees from differently completed online cohorts an optimality gap. The `sim-quality` exact comparison deliberately serves an identical zero-SLA cohort; mesh/long-run global optima remain unknown. Use `cargo run --locked --example simulate -- 10000 42 reserved` for replay-checked headless execution.

- `Simulator::step_observed` collects bounded evidence from the actual static or reserved search without changing events, RNG, diagnostics, pruning or reservations. Each payment retains at most 24 entries per tick; omitted entries are counted. Reserved candidates can come from discarded order/repair trials; never present them as independently feasible against the final allocation or as a global optimum certificate.
- `operations::Operations` is terminal-independent. It transactionally advances static and reserved runs at one shared minute and seed, using bounded dossiers (all active plus the newest 128 terminal payments), 32 events per dossier and 120 queue samples. Comparison fees apply to potentially different completed cohorts and are not optimality gaps. Its accelerated execution presets never change `demo_network()`.

- The current `--demo` launches the operations console, paused at seed 42 before minute zero, with optional `--seed`, `--scenario`, and `--strategy`. See `docs/operations-console.md`; older viewer-specific stage verification notes are historical. Keep 80x18 comparison fees and outcomes visible together; use scrollable payment/rail details for full evidence and utilization. Payment Home follows newest, while manual movement holds an ID. Search/help/drill-down pause and never consume RNG.
- `scripts/test_console.py` runs the actual binary in PTYs, verifies q/Esc/Ctrl-C zero exits plus alternate-screen and terminal-mode restoration, and writes ignored snapshots. On macOS keep a shell-like session parent alive until after checking modes: exiting the controlling session leader revokes the slave terminal and makes `tcgetattr` fail with ENOTTY even after correct app cleanup.
- An automatic tick that pauses on error must force a redraw before the event loop enters its paused blocking read. Keep successful ticks throttled; the deterministic loop test injects a failure between refresh deadlines and checks the last rendered frame before input.
- Capture the final accepted reservation timestamps in `DecisionEvidence::reserved_departures` at acceptance, independently of capped search traces. Copying only from post-tick active payments loses zero-latency same-tick completions; discarded candidates and actual departure events are not substitutes for the accepted plan. Preserve ordinary simulator events and state.
- Payment IDs and absolute deadlines grow throughout continuous execution. Size their table columns from the displayed values and wrap overflow with matching row heights; fixed widths silently merge distinct IDs and change displayed deadlines. Preserve space for the other columns and verify complete digits plus selection-driven scrolling at 80x18, including `u128::MAX` rendering fixtures.
